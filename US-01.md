# 📋 Especificación de Sprint - Historia de Usuario 1

## 🎭 Definición Global de "Definition of Done" (DoD)
Para que esta y cualquier historia subsecuente del frontend se considere oficialmente **Terminada**, debe cumplir con el siguiente estándar de calidad:
1. **Fidelidad al Sistema de Diseños (Design Tokens):** Uso obligatorio de las variables de Tailwind v4 configuradas en el archivo global `index.css` (`--color-flansly-dark`, `--color-flansly-flan`, etc.).
2. **Aislamiento Arquitectónico:** Queda estrictamente prohibido realizar llamadas HTTP directas a Axios dentro de los componentes visuales de las páginas. Todo flujo de datos debe consumirse a través de abstracciones de servicios o custom hooks.
3. **Tipado y Validación Enérgica:** Todo componente reutilizable de la interfaz debe validar la integridad de sus props entrantes utilizando la librería `prop-types`.
4. **Diseño Responsivo Defensivo:** Las vistas estructuradas deben ser adaptables, respetando un ancho contenedor máximo de `1200px` en escritorio con sidebars fluidos de `280px` y márgenes laterales fijos de `16px` en pantallas móviles.

## 🗺️ Historia de Usuario 1: Enrutamiento, Estado de Sesión y Capa de Datos
**Asignado a:** Marcelo (Líder Técnico / Arquitecto Frontend)
**Impacto Arquitectónico:** Bloqueante Crítico (Cimientos del Sistema)

### 📝 Descripción
**Como** Arquitecto de Software,
**Quiero** configurar el enrutamiento base, el estado de sesión global y el cliente HTTP unificado,
**Para** garantizar que la navegación esté protegida según el rol del usuario y que las peticiones al backend incluyan tokens de seguridad de forma automatizada.

### 🎯 Criterios de Aceptación
* **CA1 (Capa de Datos):** Crear una instancia centralizada de Axios con un interceptor automático que inyecte la cabecera `Authorization: Bearer <token>` recuperando las credenciales desde el almacenamiento local persistente (`localStorage`).
* **CA2 (Capa de Aplicación - Estado):** Desarrollar un `AuthContext` inmutable que encapsule el estado de autenticación (`user`, `token`, `isAuthenticated`, `role`), parseando el payload del JWT de forma segura sin librerías externas redundantes.
* **CA3 (Capa de Presentación - Layouts):** Diseñar los armazones estructurales `AuthLayout` (vistas públicas centradas en pantalla) y `DashboardLayout` (esquema administrativo con sidebar lateral izquierdo fijo en `280px` y contenedor de consumo centrado a `1200px`).
* **CA4 (Capa de Presentación - Seguridad):** Implementar los guardianes de navegación `<PrivateRoute />` (deniega acceso a usuarios anónimos) y `<RoleRoute />` (control por lista blanca de roles) para evitar accesos cruzados de creadores a paneles de seguidores y viceversa.
